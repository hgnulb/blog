    题目描述

    ✅ 1163. 按字典序排在最后的子串

    题意分析

    求字符串中按字典序最大的子串。未到串尾的子串延长成后缀后会更大，所以只需在全部后缀中寻找最大者。

    解法：双指针比较最大后缀

    核心思路

    [!blue]
    比较两个候选后缀，并批量淘汰起点。 维护 i<j，k 表示两后缀已经匹配的前缀长度。字符相同就延长 k，失配时利用这段相等前缀跳过一批不可能获胜的起点。

    若 s[i+k]<s[j+k]，则对 0≤t≤k，起点 i+t 的后缀都输给 j+t，可以淘汰 [i,i+k]。令 i=max(i+k+1,j)，再令 j=i+1。反之淘汰 [j,j+k]，令 j+=k+1。每次失配后 k 归零。

    一次比较积累的匹配长度，会在失配时转化为指针跳跃。两个指针只前进，因此避免逐对反复比较长公共前缀。

    解题步骤

    1. 初始化 i=0、j=1、k=0。
    2. 只要 j+k 未越界，就比较两个候选的同一偏移字符。
    3. 相等时 k 加一；失配时按较小一方批量跳过起点，并清零 k。
    4. 返回从 i 到串尾的后缀。

    示例："cacacb" 中，起点 0 与 2 匹配 cac 后出现 a<b，起点 0 到 3 都被淘汰，i 跳到 4。最终 "cb" 胜过 "b"，返回 cb。 全相同字符时，更早的后缀更长，答案就是整个字符串。

    代码实现

    class Solution {
    public String lastSubstring(String s) {
        int n = s.length();
        int i = 0;
        int j = 1;
        // k 记录两个候选后缀已经确认相等的前缀长度。
        int k = 0;

        while (j + k < n) {
            char a = s.charAt(i + k);
            char b = s.charAt(j + k);

            if (a == b) {
                k++;
            } else if (a < b) {
                // i 输了，[i, i+k] 的起点都可淘汰。
                i = Math.max(i + k + 1, j);
                j = i + 1;
                k = 0;
            } else {
                // j 输了，[j, j+k] 的起点同样被连带否定。
                j = j + k + 1;
                k = 0;
            }
        }

        return s.substring(i);
    }
}

    func lastSubstring(s string) string {
    n := len(s)
    // i、j 是候选起点，k 是已经确认相等的前缀长度。
    i, j, k := 0, 1, 0
    for j+k < n {
        a := s[i+k]
        b := s[j+k]
        if a == b {
            k++
        } else if a < b {
            // i 输了，[i, i+k] 的起点都可淘汰。
            if i+k+1 > j {
                i = i + k + 1
            } else {
                i = j
            }
            j = i + 1
            k = 0
        } else {
            // j 输了，[j, j+k] 的起点同样被连带否定。
            j = j + k + 1
            k = 0
        }
    }
    return s[i:]
}

    复杂度分析

    • 时间复杂度：$O(n)$。失配前的相等比较由本次指针跳跃摊还；末尾若一直相等，还会有至多 n 次比较。Java 构造返回子串的复制仍是线性。
    • 空间复杂度：搜索辅助空间为 $O(1)$；Java 返回子串另需对应长度的存储，Go 返回字符串切片。

    关键点总结

    [!green]

    • 答案是后缀，先减少候选类型。
    • 失配一次淘汰一段起点，不是只移动一步。
    • 每次换候选都清零 k，重新建立公共前缀。

    易错点总结

    [!yellow]

    • 较小的一方只移动一步：长重复前缀会被反复比较，失去线性效率。
    • 更新 i 时不与 j 取最大值：可能回到此前已经淘汰的位置。
    • 循环只检查 j<n：k 增大后仍可能越界，应检查 j+k。
    • 只看最大字符的首次或末次位置：首字符相同时仍需比较后续内容。
