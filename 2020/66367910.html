    题目描述

    ✅ 220. 存在重复元素 III

    题意分析

    同时要求两个不同位置的下标差不超过 k、数值差不超过 t。按原下标顺序维护窗口，再选择有序范围查询或分桶完成值差判断。

    解法一：滑动窗口 + 有序集合

    核心思路

    [!blue]

    处理当前位置前，有序集合保存此前至多 k 个位置的值。查询第一个不小于 x-t 的候选，若它也不大于 x+t，就找到了值差合格的近邻。

    这个候选是下界之后最小值，若它已经超过上界，更大值都不可能合格。先查询再加入当前值，随后删除下轮不再允许的旧位置。相同值若曾同时位于有效窗口，早已返回成功，所以继续运行时可用普通集合。

    解题步骤

    • 将值提升为宽整数。
    • 查询下界的最小后继并比较上界。
    • 未命中才加入当前值。
    • 本轮末尾移除下标 i-k，为下轮维持有效窗口。

    [1,5,9,1,5,9]、k=2、t=3 中，旧的一在新的一到来前已离开窗口，因此不能配对。

    代码实现

    class Solution {
    public boolean containsNearbyAlmostDuplicate(int[] nums, int k, int t) {
        if (k <= 0 || t < 0) {
            return false;
        }

        TreeSet<Long> set = new TreeSet<>();

        // 查询时只保存此前至多 k 个位置，不包含当前下标
        for (int i = 0; i < nums.length; i++) {
            long x = nums[i];
            // 只需检查不小于下界的最小候选，它超上界则其他值也无解
            Long ceil = set.ceiling(x - t);

            if (ceil != null && ceil <= x + t) {
                return true;
            }

            // 全部查询未命中后才写入，避免当前项与自己配对
            set.add(x);

            // 本轮末尾删除 i 减 k 的旧位置，为下一轮维护窗口
            if (i >= k) {
                set.remove((long) nums[i - k]);
            }
        }

        return false;
    }
}

    复杂度分析

    • 时间复杂度：$O(n\log(\min(n,k)+1))$，每项常数次有序集合操作。
    • 空间复杂度：$O(\min(n,k)+1)$，含插入后暂时多出的一项。

    关键点总结

    [!green]

    • 查找范围的最小候选即可，无需扫描整个集合。
    • 位置窗口按原顺序维护，不能排序输入。
    • Java 集合保存宽整数，删除旧值也使用相同类型。

    解法二：滑动窗口 + 分桶

    核心思路

    [!blue]

    按宽度 t+1 将整数数轴划成桶，同桶中任意两数差不超过 t。满足值差却不同桶的数只可能在相邻桶，因此每次只检查本桶与左右邻桶。

    同桶直接成功，相邻桶还需比较真实差值。负数桶号使用向下取整，让零两侧的桶宽一致。每桶已有项时会立即命中，所以尚未返回时每个桶只保存一个值。

    解题步骤

    • 桶宽使用宽整数计算 t+1。
    • 计算当前值桶号，负数补偿向零截断的除法。
    • 检查同桶与相邻桶，相邻时再验证差值。
    • 写入当前值，并删除下一轮过期位置所属桶。

    t=1 时桶宽二，负一与一应分属不同桶且差二，不合格；若直接向零截断，两者会被错放同桶。

    代码实现

    func containsNearbyAlmostDuplicate(nums []int, k int, t int) bool {
    if k <= 0 || t < 0 {
        return false
    }

    bucketSize := int64(t) + 1
    buckets := make(map[int64]int64)

    getBucket := func(x int64) int64 {
        if x >= 0 {
            return x / bucketSize
        }
        // 负数向下取整，避免零两侧被截断到同一个过宽桶
        return (x+1)/bucketSize - 1
    }

    // 查询时只保存此前至多 k 个位置，不包含当前下标
    for i, v := range nums {
        x := int64(v)
        id := getBucket(x)

        if _, ok := buckets[id]; ok {
            return true
        }
        // 相邻桶仅可能接近，仍要验证实际差值
        if val, ok := buckets[id-1]; ok && x-val <= int64(t) {
            return true
        }
        if val, ok := buckets[id+1]; ok && val-x <= int64(t) {
            return true
        }

        // 全部查询未命中后才写入，避免当前项与自己配对
        buckets[id] = x
        // 本轮末尾删除 i 减 k 的旧位置，为下一轮维护窗口
        if i >= k {
            old := int64(nums[i-k])
            bid := getBucket(old)
            delete(buckets, bid)
        }
    }

    return false
}

    复杂度分析

    • 时间复杂度：期望 $O(n)$，每项最多检查三个哈希桶。
    • 空间复杂度：$O(\min(n,k)+1)$，只保存有效窗口桶。

    关键点总结

    [!green]

    • 桶宽含端点差，因此取阈值加一。
    • 负数必须使用向下取整的桶号。
    • 邻桶仅表示可能接近，仍需实际差值检查。

    易错点总结

    [!yellow]

    • 先插入再查询，会把当前元素与自己配对。
    • 过期位置未删除，会接受下标距离超限的值。
    • 邻桶存在就直接成功，会把实际差值过大的配对误计。
    • 负数桶号向零截断，会扩大零附近的桶范围，误收本不接近的值。
    • Java 有序集合存放宽整数，边界运算和删除旧值都要使用相同类型。
