    一、什么是单例模式

    [!blue]
    单例模式保证一个类只有一个实例，并提供统一的访问入口。

    它适合管理需要共享、且不应重复创建的对象，例如配置中心或资源管理器。单例会引入全局状态，不应作为普通对象的默认写法。

    单例类通常包含三个要点：私有构造方法、类内部保存唯一实例、公开获取实例的方法。

    二、推荐实现

    1. 枚举

    public enum Singleton {
    INSTANCE;

    public void execute() {
        System.out.println("执行任务");
    }
}

    [!blue]
    枚举由 JVM 保证只初始化一次，天然线程安全，并能防止反射和反序列化创建新实例。没有延迟加载要求时，优先使用这种写法。

    2. 静态内部类

    public class Singleton {
    private Singleton() {
    }

    private static class SingletonHolder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}

    [!blue]
    调用 getInstance() 时才会初始化 SingletonHolder，因此支持延迟加载。类初始化由 JVM 保证线程安全，不需要额外加锁。

    3. 饿汉式

    public class Singleton {
    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {
    }

    public static Singleton getInstance() {
        return INSTANCE;
    }
}

    [!blue]
    类初始化时直接创建实例，写法简单且线程安全。适合实例创建成本低、程序运行期间一定会使用的场景。

    三、双重校验

    双重校验既支持延迟加载，也避免实例创建后每次调用都加锁。

    public class Singleton {
    private static volatile Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

    [!blue]
    执行步骤

    1. 第一次判空在锁外执行。实例已经创建时，直接返回。
    2. 实例不存在时进入同步代码块，同一时间只允许一个线程创建实例。
    3. 获取锁后再次判空，避免等待锁的线程重复创建实例。

    为什么使用 volatile

    new Singleton() 包含分配内存、初始化对象和引用赋值。volatile 可以禁止关键指令重排序，并保证实例引用对其他线程可见，避免线程读取到尚未完成初始化的对象。

    synchronized 负责保证只创建一次，volatile 负责保证实例安全发布，两者作用不同。

    四、不推荐的写法

    • 普通懒汉式：判空和创建不是原子操作，多线程可能创建多个实例。
    • 同步方法：线程安全，但每次获取实例都要进入同步区，没有必要时不使用。
    • 手动防反射、反序列化和克隆：实现复杂且容易遗漏，有此要求时直接使用枚举。

    五、如何选择

    场景 推荐写法
    默认选择，要求实现稳妥 枚举
    需要延迟加载和普通类 静态内部类
    实例简单且一定会使用 饿汉式
    需要掌握并发实现原理 双重校验

    [!red]
    单例只保证同一类加载器内的唯一实例。多进程或分布式系统中的“全局唯一”，需要依靠数据库、分布式锁等外部机制。
