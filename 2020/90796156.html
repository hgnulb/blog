    问题思考

    [!blue]

    • 请简述方法重写和方法重载的区别。
    • private、final、static 修饰的方法可以重写吗?
    • 什么叫方法的重载？构造方法可以重载吗？构造方法可以重写吗？

    面试速答

    [!purple]
    重载（Overload）是同一个类中方法名相同、参数列表不同，调用哪个方法在编译期根据参数的静态类型确定，属于静态绑定；重写（Override）是子类重新实现父类的实例方法，执行哪个版本在运行期根据对象的实际类型确定，属于动态绑定，是多态的核心体现。一句话：重载看参数列表、编译期定；重写看对象类型、运行期定。

    七维对比表

    下表从七个维度对比重载与重写，其中绑定时期一行是两者最本质的区别，其余各行都可以由它推导出来。

    对比项 方法重载 方法重写
    发生位置 同一个类中（含父子类） 父子类之间
    参数列表 必须不同 必须相同
    返回值 可以不同（不能作为区分依据） 相同或为其子类（协变返回类型）
    访问权限 无限制 不能小于被重写方法
    抛出异常 无限制 检查异常不能大于被重写方法
    绑定时期 编译期（静态绑定） 运行期（动态绑定）
    多态 编译时多态 运行时多态

    方法重写

    方法重写发生在父子类之间：子类重新实现父类中签名相同的实例方法。重写是多态的基础——通过父类引用调用被重写的方法时，实际执行哪个版本由对象的运行时类型决定，这个选择在运行期完成，称为动态绑定（动态分派）。

    向上转型时，通过父类引用调用方法需要注意以下两点：

    • 无法调用到子类中新增而父类中不存在的方法——编译器只按引用的静态类型做检查，父类里没有的方法直接编译报错。
    • 调用被子类重写的方法时，实际执行的是子类版本，这就是多态。

    重写的规则(两同两小一大)

    • 两同：方法名相同、参数列表相同。两者有一处不同就不是重写，而可能构成重载——这也是子类方法建议加 @Override 注解的原因，让编译器帮忙检查是否真的构成重写。
    • 两小之一（协变返回类型）：重写方法的返回值类型与被重写方法相同，或是其子类。例如父类方法返回 Object，子类重写时可以返回 String，这从 JDK 5 开始支持。
    • 两小之二（异常）：重写方法抛出的检查异常与被重写方法相同或是其子类，也可以不抛；但不能抛出更大范围的新检查异常，否则通过父类引用调用时，调用方按父类声明写的异常处理就会失效。运行时异常不受此限制。
    • 一大：重写方法的访问修饰符不能小于被重写方法（public > protected > default > private）。否则通过父类引用多态调用时，父类可见的方法在子类中反而不可见，破坏里氏替换。
    • private 方法不能被重写：private 方法对子类不可见、不参与继承，子类中同签名的方法只是新定义了一个与父类无关的方法。
    • 静态方法不存在重写，只有隐藏（hiding）：子类定义同签名的静态方法叫隐藏，调用哪个版本在编译期按引用的静态类型决定，不具有多态性；把静态方法「重写」成实例方法（或反之）会直接编译报错。

    方法重写的注意事项

    [!amber]

    • 实例方法不能覆盖静态方法，静态方法也不能隐藏实例方法（编译报错）。
    • 如果不能继承一个方法（private 方法、构造方法），则不能重写这个方法。所以构造方法可以重载、但不能被重写。
    • 隐藏与重写的关键区别：静态方法调用在编译期按引用的静态类型绑定，不具有多态性。所以下面例子中 A a = new B(); a.fun(); 执行的是 A.fun() 而不是 B.fun()。
    方法类型 能否被继承 能否被重载 能否被重写 能否被隐藏
    private 方法 否 是 否 否
    构造方法 否 是 否 否
    final 方法(实例) 是 是 否 否
    final 方法(静态) 是 是 否 不可以被 static 方法隐藏
    static 方法 是 是 否 可以被 static 方法隐藏

    示例一：静态方法的隐藏不具有多态性

    class A {
    static void fun() {
        System.out.println("A.fun()");
    }
}

class B extends A {
    static void fun() {
        System.out.println("B.fun()");
    }
}

public class Main {
    public static void main(String[] args) {
        A a = new B();
        a.fun();

        B b = new B();
        b.fun();
    }
}

    [!green-fold] 运行结果
    A.fun()

    B.fun()

    为什么：静态方法在编译期按引用的静态类型绑定，a 的静态类型是 A，所以即使它实际指向 B 的对象，执行的仍是 A.fun()；这正是「隐藏」与「重写」的区别。

    示例二：静态方法隐藏，父类引用调用父类版本

    class Derived {
    protected static void getDetails() {
        System.out.println("Derived class");
    }
}

public class Test extends Derived {
    protected static void getDetails() {
        System.out.println("Test class");
    }

    public static void main(String[] args) {
        Derived obj = new Test();
        obj.getDetails();
    }
}

    [!green-fold] 运行结果
    Derived class

    为什么：getDetails() 是静态方法，obj 的静态类型是 Derived，编译期就绑定到 Derived.getDetails()，与对象的实际类型无关。

    示例三：把 static 去掉，同样的代码立刻变成多态

    class Derived {
    protected void getDetails() {
        System.out.println("Derived class");
    }
}

public class Test extends Derived {
    protected void getDetails() {
        System.out.println("Test class");
    }

    public static void main(String[] args) {
        Derived obj = new Test();
        obj.getDetails();
    }
}

    [!green-fold] 运行结果
    Test class

    为什么：与示例二只差一个 static——实例方法构成重写，运行期按对象的实际类型动态绑定，obj 实际指向 Test 对象，所以执行子类版本。示例二与示例三对照着记，隐藏与重写的区别一目了然。

    示例四：同一个对象上，静态方法与实例方法行为不同

    class Base {
    public static void display() {
        System.out.println("Static or class method from Base");
    }

    public void print() {
        System.out.println("Non-static or Instance method from Base");
    }
}

class Derived extends Base {
    public static void display() {
        System.out.println("Static or class method from Derived");
    }

    public void print() {
        System.out.println("Non-static or Instance method from Derived");
    }
}

public class Test {
    public static void main(String[] args) {
        Base derived = new Derived();
        derived.display();
        derived.print();
    }
}

    [!green-fold] 运行结果
    Static or class method from Base

    Non-static or Instance method from Derived

    为什么：同一个引用 derived，静态方法 display() 按静态类型 Base 编译期绑定，实例方法 print() 按实际类型 Derived 运行期绑定，两条规则同框对比。

    示例五：标准的重写与多态

    class Base {
    public void fun() {
        System.out.println("Base fun");
    }
}

class Derived extends Base {
    @Override
    public void fun() {
        System.out.println("Derived fun");
    }

    public static void main(String[] args) {
        Base obj = new Derived();
        obj.fun();
    }
}

    [!green-fold] 运行结果
    Derived fun

    为什么：这是最标准的重写：父类引用指向子类对象，运行期动态绑定到子类版本，即运行时多态。

    示例六：private 方法不能通过父类引用调用

    class Base {
    private void fun() {
        System.out.println("Base fun");
    }
}

class Derived extends Base {
    private void fun() {
        System.out.println("Derived fun");
    }

    public static void main(String[] args) {
        Base obj = new Derived();
        obj.fun();
    }
}

    [!red-fold] 运行结果
    编译错误。'fun()' 在 'base.Base' 中具有 private 访问权限

    为什么：编译器按引用的静态类型 Base 检查，Base.fun() 是 private 的，在类外（main 位于 Derived 中）不可见，直接编译失败——private 方法根本不参与重写。

    示例七：强转后调用的是子类自己新定义的方法

    class Base {
    private void fun() {
        System.out.println("Base fun");
    }
}

class Derived extends Base {
    private void fun() {
        System.out.println("Derived fun");
    }

    public static void main(String[] args) {
        Base obj = new Derived();
        ((Derived) obj).fun();
    }
}

    [!green-fold] 运行结果
    Derived fun

    为什么：强转成 Derived 后，编译器按 Derived 检查可见性，main 就在 Derived 内部，能访问自己的 private 方法；但 Derived.fun() 与 Base.fun() 是两个互不相关的方法，不构成重写。

    示例八：内部类中的 private 方法

    class Outer {
    private String msg = "GeeksforGeeks";

    private void fun() {
        System.out.println("Outer fun()");
    }

    class Inner extends Outer {
        private void fun() {
            System.out.println("Accessing Private Member of Outer: " + msg);
        }
    }

    public static void main(String[] args) {
        Outer o = new Outer();
        Inner i = o.new Inner();
        i.fun();
        o = i;
        o.fun();
    }
}

    [!green-fold] 运行结果
    Accessing Private Member of Outer: GeeksforGeeks

    Outer fun()

    为什么：内部类可以访问外部类的私有成员，所以 i.fun() 能打印 msg；而 private 方法在编译期按引用的静态类型绑定，o 的静态类型是 Outer，因此 o.fun() 执行的是 Outer.fun()——即使 o 实际指向 Inner 对象。

    方法重载

    方法重载是指在一个类中，多个方法的方法名相同，但是参数列表不同。参数列表不同指的是参数个数、参数类型或者参数的顺序不同，比如一个类中的多个构造方法就是典型的重载。

    在编译器的眼里，方法名称 + 参数类型 + 参数个数组成一个唯一键，称为方法签名，编译器通过这个唯一键决定调用哪个重载方法。

    也就是说，调用哪个重载方法在编译期就已经确定，只看参数的静态类型，这称为静态绑定（静态分派）；而重写方法的选择发生在运行期（动态绑定），这是重载与重写最本质的区别。

    [!amber]
    注意，方法返回值并不是方法签名的一部分，所以不能定义两个方法名、参数类型、参数个数完全相同而只有返回类型不同的方法——这不构成重载，直接编译报错。

    方法重载的规则

    • 方法名必须相同，参数列表必须不同。参数列表不同包括参数个数、参数类型、参数顺序不同。
    • 方法的返回值类型、访问权限、抛出的异常可以相同也可以不相同——它们都不能作为区分重载的依据。
    • 方法重载可以声明新的或更广的检查异常（重写不允许，重载不受限）。
    • 方法重载可以发生在同一个类中，也可以发生在子类中（子类重载父类的方法）。
    • main 方法和构造方法也可以被重载；但构造方法不能被继承，所以不能被重写。

    [!amber]
    如果调用 methodForOverload(7) 的话，猜猜到底调用的是谁呢？

    编译器在重载方法中，选择合适的目标方法的顺序如下

    1. 精确匹配：参数的静态类型与形参完全一致。
    2. 基本类型自动向上转换：如 int → long → float → double，转换成表示范围更大的基本类型。
    3. 自动装箱与拆箱：如 int → Integer。
    4. 沿继承链向上转型匹配：如 Integer → Number → Object，从最近的父类依次尝试。
    5. 可变参数匹配：可变参数的优先级最低，前面全部匹配失败才轮到它。

    记忆要点：先基本类型加宽，再装箱，最后可变参数；如果某一步存在多个「同样合适」的候选（比如 null 同时匹配两个互无父子关系的引用类型），编译器会报「方法调用不明确」的错误。

    示例：null 传给重载方法时选更具体的类型

    public class GFG {
    private GFG(Object o) {
        System.out.println("Object");
    }

    private GFG(double[] d) {
        System.out.println("double array");
    }

    public static void main(String[] args) {
        new GFG(null);
    }
}

    [!green-fold] 运行结果
    double array

    为什么：null 可以赋给任何引用类型，两个构造方法都可行；重载决议规则要求选择最具体（most specific）的类型，double[] 是 Object 的子类型，比 Object 更具体，所以选中数组版本。若两个候选类型互无父子关系（如 String 和 Integer），则编译器报歧义错误。

    面试选择题

    下列关于方法重载的说法中，正确的是（ ）

    [!blue]

    • A. 方法名相同，参数的个数不同可以形成方法重载。
    • B. 方法名相同，参数的类型不同可以形成方法重载。
    • C. 方法名相同，参数的类型排列顺序不同可以形成方法重载。
    • D. 方法名相同，返回值类型不同可以形成方法重载。

    [!green-fold] 参考答案
    ABC

    解析：参数个数、类型、顺序不同都构成参数列表不同，均可形成重载；返回值不是方法签名的一部分，只有返回值不同不构成重载，D 错。

    关于方法重载的描述，以下选项中哪些是正确的（ ）

    [!blue]

    • A. 方法名必须一致
    • B. 返回值类型必须一致
    • C. 参数个数必须一致
    • D. 参数的个数或类型不一致

    [!green-fold] 参考答案
    AD

    解析：重载要求方法名相同、参数列表不同（个数或类型不一致），A、D 对；返回值类型没有限制，B 错；参数个数恰恰可以不同，C 错。

    在 Java 中，以下关于方法重载和方法重写描述正确的是（ ）

    [!blue]

    • A. 方法重载和方法的重写实现的功能相同
    • B. 方法重载出现在父子关系中，方法重写是在同一类中
    • C. 方法重载的返回值类型必须一致，参数项必须不同
    • D. 方法重写的返回值类型必须相同或相容

    [!green-fold] 参考答案
    D

    解析：重写的返回值须与被重写方法相同或为其子类（协变返回类型），D 对；A 两者机制和目的都不同；B 把重载与重写的发生位置说反了；C 重载对返回值没有一致性要求。

    Java 里关于方法的重写和重载，下面说法正确的是（ ）

    [!blue]

    • A. 方法重写是指父类与子类之间多态性的一种表现
    • B. 方法重载是指同一个类中多态性的一种表现
    • C. 子类中定义的某方法与其父类中的某方法有相同的签名 (名称、参数、返回值)，称之为方法重写
    • D. 一个类中定义了多个同名的方法，但方法签名 (名称、参数、返回值) 不相同，称之为方法重载

    [!green-fold] 参考答案
    ABCD

    解析：本题采用宽口径说法：重写是运行时多态（A），重载常被称为编译时多态（B），C、D 按题面的「签名」定义描述重写与重载。严格地说返回值不属于方法签名，但在本题语境下 C、D 视为正确。

    在 Java 中区分方法重载的依据是（ ）

    [!blue]

    • A. 不同的形参名称
    • B. 不同的返回值类型
    • C. 不同的形参列表
    • D. 不同的访问权限

    [!green-fold] 参考答案
    C

    解析：区分重载的唯一依据是形参列表（个数、类型、顺序）；形参名称、返回值类型、访问权限都不参与方法签名的区分。

    以下哪些项可以让两个同名的方法实现合法的重载（ ）

    [!blue]

    • A. 形式参数个数不同
    • B. 返回值类型不同
    • C. 形式参数类型不同
    • D. 形式参数名称不同

    [!green-fold] 参考答案
    AC

    解析：参数个数或类型不同才是合法重载；只有返回值不同或只有参数名不同，编译器视为同一个方法签名，直接报重复定义错误。

    下列选项中，可以和 int max(int a, int b, double c) 方法构成重载关系的是（ ）

    [!blue]

    • A. double max(int a, int b)
    • B. void max(int a, double b, int c)
    • C. double max(double a, double b)
    • D. int max(int x, int y, double z)

    [!green-fold] 参考答案
    ABC

    解析：A 参数个数不同、B 参数类型顺序不同、C 参数个数和类型都不同，均构成重载；D 的参数列表是 (int, int, double)，与原方法完全相同（形参名不算），属于重复定义。

    下面哪个方法是 public void example(){...} 的重载方法（ ）

    [!blue]

    • A. public void Example(int m) {...}
    • B. public int example() {...}
    • C. public void example2() {...}
    • D. public int example(int m, float f) {...}

    [!green-fold] 参考答案
    D

    解析：A、C 方法名不同（Java 区分大小写），不是重载；B 只有返回值不同，不构成重载且会编译报错；D 方法名相同、参数列表不同，是合法重载（返回值顺带不同没有影响）。
