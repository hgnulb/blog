    Java 方法重载与重写的区别

    2020-05-12 HGNULB 约 10 分钟
    文章信息 1 个分类 · 1 个标签
    分类
    Java 专题
    标签
    Java 基础

    重载提供不同的参数入口，重写提供不同的实例方法实现。 重载在编译期选定方法签名；普通实例调用在运行期根据接收者对象选择对应实现。

    一、重载：不同参数

    1.1 三种参数入口

    如果分别命名为 printText()、printNumber() 和 printCopies()，调用方需要记住多个名字。对于职责一致、只是输入形式不同的操作，重载可以让接口更统一：

    public class OverloadExample {
    static void print(String text) {
        System.out.println("文本：" + text);
    }

    static void print(int number) {
        System.out.println("整数：" + number);
    }

    static void print(String text, int copies) {
        for (int i = 0; i < copies; i++) {
            print(text);
        }
    }

    public static void main(String[] args) {
        print("Java");
        print(8);
        print("Java", 2);
    }
}

    输出：

    文本：Java
整数：8
文本：Java
文本：Java

    前两次调用按参数类型区分，分别选中 print(String) 和 print(int)；第三次按参数数量选中 print(String, int)，再复用单份文本打印的方法。三个方法可以同时存在，互不替代。

    这就是方法重载（Overloading）：方法名相同，参数类型列表不同。它不要求继承关系，也可以涉及继承而来的方法。静态方法和实例方法都可以重载。

    1.2 方法签名

    对于本文的非泛型方法，方法签名由方法名和参数类型列表组成。参数的数量、类型及顺序都会影响签名，返回类型和参数名称不在其中。

    因此，print(String, int) 与 print(int, String) 也能构成重载；但如果两个参数都是 int，只交换它们的名称，就没有产生新签名。仅修改返回类型不能构成重载，仅修改访问权限或异常声明也不行。

    选择哪个重载在编译期完成，不要求实参和形参的类型总是完全一致。

    1.3 类型转换会影响重载选择

    这里同时提供接收 long、Integer 和可变参数的三个入口：

    public class ConversionExample {
    static void select(long value) {
        System.out.println("基本类型拓宽");
    }

    static void select(Integer value) {
        System.out.println("包装类型匹配");
    }

    static void select(int... values) {
        System.out.println("数组长度：" + values.length);
    }

    public static void main(String[] args) {
        select(1);
        select(Integer.valueOf(1));
        select(1, 2);
        select(new int[] {1, 2});
    }
}

    输出：

    基本类型拓宽
包装类型匹配
数组长度：2
数组长度：2

    select(1) 选择 select(long)：int 到 long 只需拓宽，不需要装箱，因此先于需要装箱的 select(Integer) 被考虑。

    select(Integer.valueOf(1)) 选择 select(Integer)：实参已经是 Integer，可以直接匹配，不需要先拆箱再转换为 long。

    后两次调用都执行 select(int...)，接收到的都是长度为 2 的 int[]。区别在调用处：select(1, 2) 需要把两个整数收集为一个数组；select(new int[] {1, 2}) 则直接传入调用方创建好的数组，不需要再次收集参数。

    这也说明，不能把声明了 ... 的方法一律排到最后。直接传入兼容数组时，它可以按一个固定的数组参数参与匹配；只有需要收集数组的调用，才进入可变参数调用阶段。

    编译器按下面的顺序查找适用方法：

    [!blue]

    1. 先按固定参数匹配：实参与形参数量一致，类型相同或允许拓宽转换，不需要装箱、拆箱，也不把多个实参收集成数组。
    2. 再允许装箱、拆箱：第一步没有适用方法时，尝试需要装箱、拆箱的固定参数调用，例如将 int 装箱为 Integer。
    3. 最后尝试可变参数调用：前两步都没有适用方法时，才把末尾的零个或多个实参收集为数组。

    找到适用方法后，不再进入后续阶段，而是在该阶段选择最具体的方法。如果无法确定唯一最具体的方法，调用会因歧义而编译失败；三个阶段都没有适用方法，也会编译失败。

    二、重写：不同实现

    2.1 通过父类引用调用子类方法

    重载增加输入形式，重写则保留原有方法入口。彩色打印机可以保持 print(String) 的签名不变，提供自己的实现：

    public class OverrideExample {
    static class Printer {
        public void print(String text) {
            System.out.println("普通打印：" + text);
        }
    }

    static class ColorPrinter extends Printer {
        @Override
        public void print(String text) {
            System.out.println("彩色打印：" + text);
        }
    }

    public static void main(String[] args) {
        Printer printer = new ColorPrinter();

        printer.print("Java");
    }
}

    输出：

    彩色打印：Java

    printer 的声明类型是 Printer，所以编译器先确认这个类型提供了可调用的 print(String)。但它实际引用的是 ColorPrinter 对象，运行时便执行子类的实现。

    这就是方法重写（Overriding）：子类为父类可继承的实例方法提供新的实现。根据接收者对象的实际类型选择实现，称为动态分派。

    这里的声明类型与实际对象类型，分别对应编译时类型和运行时类型。前者决定调用处能看到哪些方法，后者决定普通实例调用最终执行哪份重写实现。

    2.2 重写约束

    重写不是任意修改父类方法。调用方原本能通过父类类型完成的调用，不能因为换成子类对象就失去基本保证：

    [!blue]

    • 方法名和参数：本文非泛型示例中应保持一致。把 print(Object) 改成 print(String) 是增加一个重载，不是重写原方法。
    • 返回类型：引用类型可以相同或更具体，例如父方法返回 Number，子方法返回 Integer，这称为协变返回。基本类型和 void 则必须一致，不能把 int 改成 long。
    • 访问权限不能收紧：可以扩大。父方法是 public，子方法就不能改成 protected。
    • 受检异常不能超出父方法允许的范围：可以不声明；若声明，每种受检异常都必须落在父方法允许的类型范围内。例如父方法声明 java.io.IOException，子方法可以声明 java.io.FileNotFoundException，但不能扩大为 Exception。非受检异常不受此限制。

    这些是声明上的兼容要求，不意味着方法必须实际抛出异常。行为上，重写实现也应遵守原方法的约定，不能只满足签名就随意改变语义。

    重写时建议始终添加 @Override，让编译器检查方法名、参数等是否正确。它不会改变分派规则；不写注解，只要符合条件，方法仍然构成重写。

    private 方法和构造方法不被子类继承；final 方法不能重写。若直接父类在另一个包中声明了包级方法，子类声明同签名方法并不构成对该方法的重写。不要只凭“方法名和参数一样”就认定是重写。

    三、先选签名，再找实现

    父类声明两个 print 重载，子类只重写 print(Object)：

    public class DispatchExample {
    static class Printer {
        public void print(Object value) {
            System.out.println("普通打印：Object");
        }

        public void print(String value) {
            System.out.println("普通打印：String");
        }
    }

    static class ColorPrinter extends Printer {
        @Override
        public void print(Object value) {
            System.out.println("彩色打印：Object");
        }
    }

    public static void main(String[] args) {
        Printer printer = new ColorPrinter();
        Object value = "Java";

        printer.print(value);
        printer.print("Java");
    }
}

    输出：

    彩色打印：Object
普通打印：String

    3.1 print(Object)：子类实现

    编译器从 printer 的编译时类型 Printer 查找候选方法。value 的编译时类型是 Object，所以选定 print(Object)。运行时，实际接收者是 ColorPrinter，它重写了这个签名的方法，最终执行子类实现。

    value 实际保存字符串不会改变这一过程。编译器不能把一个 Object 类型的表达式直接当成 String 实参，运行时也不会重新选择 print(String)。

    3.2 print(String)：父类实现

    字符串字面量的类型是 String，两个重载都适用，其中 print(String) 更具体。子类没有重写这个签名的方法，因此执行继承的父类实现。

    [!green]

    编译期选签名，运行期找实现。 对这里的普通实例调用，第二步只寻找已选定签名对应的重写实现，不会按实参对象的运行时类型重新选择重载。

    子类新增的重载，也不会自动成为父类引用调用时的候选方法。改变参数类型会产生不同的签名；协变返回则保留原签名，只让返回的引用类型更具体。

    四、静态方法隐藏

    同名静态方法与实例方法的调用规则不同。这里通过对象变量调用静态方法仅用于说明区别，实际代码应使用类名调用。

    public class HidingExample {
    static class Printer {
        static String type() {
            return "普通打印机";
        }
    }

    static class ColorPrinter extends Printer {
        static String type() {
            return "彩色打印机";
        }
    }

    public static void main(String[] args) {
        Printer printer = new ColorPrinter();

        System.out.println(printer.type());
        System.out.println(ColorPrinter.type());
    }
}

    输出：

    普通打印机
彩色打印机

    静态方法属于类。printer 的声明类型是 Printer，所以第一行调用父类静态方法，与实际对象类型无关。子类的同签名静态方法属于隐藏，不参与实例方法的动态分派。使用 Printer.type() 和 ColorPrinter.type() 可以直接表明各自的调用目标。

    五、常见误区

    5.1 返回类型不能区分重载

    假设同一个类同时声明 int parse(String text) 和 long parse(String text)，它们的签名都是 parse(String)。这不是等调用时才发生歧义，而是方法声明本身就重复了，编译器会直接拒绝。

    即使调用方用不同类型的变量接收结果，也无法解决重复声明。两种转换的意图不同，可以直接命名为 toInt(String) 和 toLong(String)。

    5.2 null 的重载歧义

    null 可以转换为不同的引用类型。当两个重载的参数类型互不为子类型时，编译器可能无法确定该选哪个。显式转换能说明调用意图：

    public class NullOverload {
    static void print(String value) {
        System.out.println("String 版本");
    }

    static void print(Integer value) {
        System.out.println("Integer 版本");
    }

    public static void main(String[] args) {
        print((String) null);
        print((Integer) null);
    }
}

    输出：

    String 版本
Integer 版本

    两行输出分别来自 print(String) 和 print(Integer)。显式转换告诉编译器应按哪种类型匹配参数；实参的值仍然是 null，并没有创建字符串或整数对象。

    调用 print(null) 时，两个方法都适用，但 String 与 Integer 互不为子类型，没有唯一更具体的方法，调用就会编译失败。

    不过，传入 null 并不总有歧义。如果重载的参数是 Object 和 String，编译器会选中更具体的 String 版本。关键不是 null 本身，而是候选参数类型之间的关系。

    六、总结

    比较项 方法重载 方法重写
    解决的问题 同一种操作接受不同输入 子类提供不同的实例方法行为
    参数类型列表 不同 本文非泛型示例中相同
    返回类型 不能单独用来区分重载 引用类型允许协变
    继承关系 不要求，也可涉及继承的方法 需要父类型与子类型的关系
    调用选择 编译期选择方法签名 运行期选择对应的重写实现

    重载提供不同的参数入口，重写让子类改变实例方法的行为，静态隐藏中的同名方法则分别属于父类和子类。判断普通实例调用时，先在编译期选定签名，再根据接收者对象寻找实现；静态方法按编译期确定的类调用，不根据对象的实际类型切换。
