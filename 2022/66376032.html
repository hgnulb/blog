    题目描述

    ✅ 727. 最小窗口子序列

    题意分析

    寻找源串中最短的连续窗口，使目标串是其子序列。窗口长度相同取最左者，匹配必须保持目标字符顺序。

    解法：双指针扫描 + 回溯收缩

    核心思路

    [!blue]

    先向右贪心找到最早完成匹配的终点，再从该终点向左倒序匹配，收紧到最靠右的合法起点，形成当前最短窗口。

    记录候选后从新起点后一格重启。被跳过的更早起点只会给出相同或更长窗口；若剩余后缀连一次目标都无法匹配，则可以结束。

    解题步骤

    • 正向扫描，目标匹配完才进入收缩。
    • 固定右端，反向匹配直到找到目标首字符对应位置。
    • 严格更短才替换答案，保留最左平局。
    • 从收紧起点加一继续。

    abcdebdde 匹配 bde，得到同长的 bcde 与 bdde，返回更左的 bcde。

    代码实现

    // 然后向左回溯，尽量收缩窗口以得到最短左边界。
class Solution {
    public String minWindow(String s, String t) {
        int n = s.length();
        int m = t.length();
        int bestLen = Integer.MAX_VALUE;
        int bestStart = -1;
        int i = 0;

        while (i < n) {
            int j = i;
            int k = 0;

            while (j < n && k < m) {
                if (s.charAt(j) == t.charAt(k)) {
                    k++;
                }
                j++;
            }

            // 剩余后缀已不能完成匹配，更靠右起点也无解
            if (k < m) {
                break;
            }

            // 固定最早匹配终点，反向寻找最靠右的合法起点
            int end = j - 1;
            k = m - 1;
            while (end >= i) {
                if (s.charAt(end) == t.charAt(k)) {
                    k--;
                    if (k < 0) {
                        break;
                    }
                }
                end--;
            }

            int start = end;
            int len = j - start;
            if (len < bestLen) {
                bestLen = len;
                bestStart = start;
            }

            // 越过已经收紧的起点，避免重复考察被支配窗口
            i = start + 1;
        }

        if (bestStart == -1) {
            return "";
        }
        return s.substring(bestStart, bestStart + bestLen);
    }
}

    // 然后向左回溯，尽量收缩窗口以得到最短左边界。
func minWindow(s string, t string) string {
    n := len(s)
    m := len(t)
    bestLen := n + 1
    bestStart := -1
    i := 0

    for i < n {
        j := i
        k := 0

        for j < n && k < m {
            if s[j] == t[k] {
                k++
            }
            j++
        }

        // 剩余后缀已不能完成匹配，更靠右起点也无解
        if k < m {
            break
        }

        // 固定最早匹配终点，反向寻找最靠右的合法起点
        end := j - 1
        k = m - 1
        for end >= i {
            if s[end] == t[k] {
                k--
                if k < 0 {
                    break
                }
            }
            end--
        }

        start := end
        length := j - start
        if length < bestLen {
            bestLen = length
            bestStart = start
        }

        // 越过已经收紧的起点，避免重复考察被支配窗口
        i = start + 1
    }

    if bestStart == -1 {
        return ""
    }
    return s[bestStart : bestStart+bestLen]
}

    复杂度分析

    • 时间复杂度：$O(nm)$，n、m 为源串与目标串长度。按源位置与目标匹配进度分摊重复扫描，每个位置的重扫对应不同进度，合计不超过这一量级；单个窗口可能跨越很长的无关字符段，不能把窗口长度直接算成 m。
    • 空间复杂度：$O(1)$，仅保存匹配下标与最佳窗口，不计返回字符串。

    关键点总结

    [!green]

    • 子序列要求顺序，字符数量足够不代表匹配成功。
    • 正向终点采用排他下标 j，长度为 j 减起点。

    易错点总结

    [!yellow]

    • 尚未完整匹配就进行反向收缩，会把不合法窗口当候选。
    • 反向目标下标已到负一仍继续读取，会越界。
    • 平局也覆盖，会丢掉先找到的最左窗口。
