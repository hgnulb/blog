    LeetCode 1642. 可以到达的最远建筑

    题目描述

    ✅ 1642. 可以到达的最远建筑

    题意分析

    上楼可花等于高度差的砖块，也可用一架梯子；下楼不消耗资源。梯子应留给已遇到的最大上升段。

    解法：最小堆维护梯子分配

    核心思路

    [!blue]

    用小根堆保存暂时分配梯子的上升高度。堆中数量超过梯子数时，取出最小上升改用砖块；剩下的就是当前最值得用梯子的较大上升。

    处理到某一步后，这种分配使经过这些上升所花砖块最少。如果仍超过预算，就不存在能跨过当前边的其他分配。

    解题步骤

    • 非正高度差直接跳过。
    • 正高度差加入堆。
    • 超出梯子名额就弹出最小差值并扣砖。
    • 砖块不足返回当前建筑下标，否则最终返回末下标。

    [4,2,7,6,9,14,12]、五块砖一架梯子，走到九时用三块砖、梯子覆盖五；下一段五仍需要额外砖，最远下标四。 [1,4]、三块砖且没有梯子，恰好跨过高度差三，可到下标一。

    代码实现

    class Solution {
    // 梯子适合留给目前见过的较大高度差，砖块适合支付较小高度差，这是贪心选择的核心。
    public int furthestBuilding(int[] heights, int bricks, int ladders) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        for (int i = 0; i < heights.length - 1; i++) {
            int diff = heights[i + 1] - heights[i];

            // 平地和下坡不消耗资源，也不加入分配候选。
            if (diff <= 0) {
                continue;
            }

            // 先把当前上升暂交给梯子，超额后再淘汰最小上升。
            minHeap.offer(diff);

            if (minHeap.size() > ladders) {
                // 超出梯子名额时，把最小上升改为用砖。
                bricks -= minHeap.poll();

                if (bricks < 0) {
                    // 无法跨过当前边，最远仍是出发建筑。
                    return i;
                }
            }
        }

        return heights.length - 1;
    }
}

    import "container/heap"

type MinHeap []int

func (h MinHeap) Len() int {
    return len(h)
}

func (h MinHeap) Less(i int, j int) bool {
    return h[i] < h[j]
}

func (h MinHeap) Swap(i int, j int) {
    h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x any) {
    *h = append(*h, x.(int))
}

func (h *MinHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func furthestBuilding(heights []int, bricks int, ladders int) int {
    minHeap := &MinHeap{}
    heap.Init(minHeap)

    for i := 0; i < len(heights)-1; i++ {
        diff := heights[i+1] - heights[i]
        // 平地和下坡不消耗资源，也不加入分配候选。
        if diff <= 0 {
            continue
        }

        // 先把当前上升暂交给梯子，超额后再淘汰最小上升。
        heap.Push(minHeap, diff)
        if minHeap.Len() > ladders {
            // 超出梯子名额时，把最小上升改为用砖。
            bricks -= heap.Pop(minHeap).(int)
            if bricks < 0 {
                // 无法跨过当前边，最远仍是出发建筑。
                return i
            }
        }
    }

    return len(heights) - 1
}

    复杂度分析

    • 时间复杂度：$O(n\log(L+2))$，L 为梯子数。
    • 空间复杂度：$O(\min(n,L+1))$，堆仅保留当前梯子候选，加入时至多临时多一项。

    关键点总结

    [!green]

    • 梯子覆盖一段上升，不需要等高于梯子数量的固定窗口。
    • 失败发生在从 i 到 i+1 的边，因此返回 i。

    易错点总结

    [!yellow]

    • 把下降值加入堆后再扣除，会产生凭空增加砖块的错误。
    • 使用大根堆弹出最大上升付砖，资源分配方向相反。
    • 一开始固定梯子用途不再调整，可能浪费在较小高度差上。
