    题目描述

    ✅ 1242. 多线程网页爬虫

    题意分析

    并行抓取起点可达的同主机页面。除普通图遍历外，还要保证同一页面只有一个任务处理，并在全部任务完成后才返回。

    解法：并发可达性遍历

    核心思路

    [!blue]
    原子去重决定任务所有权。 Java 通过并发集合 add 的返回值决定是否创建子任务；Go 在同一把锁内完成查询、标记和任务计数，只有新发现者负责启动抓取。慢速 getUrls 放在锁外。

    按任务完成判定结束，而不是看队列是否为空。 Java 父任务用 invokeAll 等待全部子任务，根任务返回代表任务树完成；Go 在启动协程前 Add，结束时 Done，主协程 Wait 等计数归零。

    父任务尚未结束时先登记新任务，保证从发现子页面到协程真正启动之间，完成计数不会提前归零。等待结束后再读取结果集合。

    解题步骤

    1. 起点先加入 visited，再启动首个任务。
    2. 任务抓取自己的页面并过滤外部主机链接。
    3. 对新 URL 原子取得处理权，登记并派生子任务。
    4. Java 等待子任务树结束，Go 等待全部计数归零。
    5. 所有写入完成后返回 URL 集合；Java 在 finally 中关闭专用线程池。

    示例：页面 A、B 同时发现 C，只有一个任务能成功标记 C，并为它登记抓取任务。另一个直接跳过。即使当前没有待启动任务，只要仍有页面正在抓取，也不能提前返回。

    代码实现

    class Solution {
    public List<String> crawl(String startUrl, HtmlParser htmlParser) {
        String host = getHost(startUrl);
        Set<String> visited = java.util.concurrent.ConcurrentHashMap.newKeySet();
        visited.add(startUrl);

        java.util.concurrent.ForkJoinPool pool = new java.util.concurrent.ForkJoinPool();
        try {
            // 等待起点任务树全部完成后，才读取结果集合。
            pool.invoke(new CrawlTask(startUrl, host, htmlParser, visited));
        } finally {
            pool.shutdown();
        }

        return new ArrayList<>(visited);
    }

    private static class CrawlTask extends java.util.concurrent.RecursiveAction {
        private final String url;
        private final String host;
        private final HtmlParser parser;
        private final Set<String> visited;

        CrawlTask(String url, String host, HtmlParser parser, Set<String> visited) {
            this.url = url;
            this.host = host;
            this.parser = parser;
            this.visited = visited;
        }

        @Override
        protected void compute() {
            List<CrawlTask> tasks = new ArrayList<>();
            for (String next : parser.getUrls(url)) {
                if (!host.equals(getHost(next))) {
                    continue;
                }
                // 原子取得新页面的处理权，只有成功者登记子任务。
                if (visited.add(next)) {
                    tasks.add(new CrawlTask(next, host, parser, visited));
                }
            }
            // 等待所有子任务结束，父任务完成才代表整棵子任务树完成。
            invokeAll(tasks);
        }
    }

    private static String getHost(String url) {
        int start = 7;
        int slash = url.indexOf('/', start);
        if (slash == -1) {
            return url.substring(start);
        }
        return url.substring(start, slash);
    }
}

    import "sync"

func crawl(startUrl string, htmlParser HtmlParser) []string {
	host := getHost(startUrl)

	var mu sync.Mutex
	visited := map[string]struct{}{startUrl: {}}

	var wg sync.WaitGroup
	var walk func(u string)
	walk = func(u string) {
		// 当前任务结束时注销，父任务派生期间始终保持计数。
		defer wg.Done()
		for _, next := range htmlParser.GetUrls(u) {
			if getHost(next) != host {
				continue
			}
			mu.Lock()
			if _, ok := visited[next]; ok {
				mu.Unlock()
				continue
			}
			// 查重、标记和登记在同一锁内完成，避免重复任务。
			visited[next] = struct{}{}
			wg.Add(1)
			mu.Unlock()

			// 新任务已登记后再启动，防止等待计数提前归零。
			go walk(next)
		}
	}

	wg.Add(1)
	go walk(startUrl)
	// 计数归零后不再有并发写入，才可遍历结果 map。
	wg.Wait()

	res := make([]string, 0, len(visited))
	for u := range visited {
		res = append(res, u)
	}
	return res
}

func getHost(url string) string {
	for i := 7; i < len(url); i++ {
		if url[i] == '/' {
			return url[7:i]
		}
	}
	return url[7:]
}

    复杂度分析

    • 时间复杂度：本地总工作量期望为 $O((V+E)L)$，并抓取 V 个页面；并发影响实际耗时，但耗时还取决于接口延迟、调度和可用并发资源。
    • 空间复杂度：设同时保留的接口返回链接数最多为 B，URL 长度上界为 L。已访问集合、任务状态和这些返回列表合计占 $O((V+B)L)$。

    关键点总结

    [!green]

    • 查重与标记原子完成，分开做会重复安排任务。
    • 先 Add 再启动，当前父任务保持在计数中。
    • 慢调用不持全局锁，否则抓取会互相阻塞。
    • Go 返回后不再有写入，才能安全遍历普通 map。

    易错点总结

    [!yellow]

    • 普通集合无同步地并发写入：不满足线程安全要求。
    • 在子协程启动后才 Add：Wait 可能先看到零并返回。
    • 遗漏 Done 或等待子任务：分别可能导致无法结束或结果不完整。
    • 工作线程都向同一个已满的有界队列派发任务：可能全部阻塞在生产端，没有线程继续消费。
