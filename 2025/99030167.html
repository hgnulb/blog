    题目描述

    ✅ 397. 整数替换

    题意分析

    偶数必须除二，奇数可以加一或减一，求变成一的最少操作数。输入最大整数的加一需要宽整数。

    解法：贪心 + 位运算

    核心思路

    [!blue]

    偶数直接右移。奇数观察低两位：末尾零一时减一得到更多末尾零；末尾一一时加一通过进位消除连续的一，随后可以连续右移。

    三是特殊情况，减到二再到一只需两步，比加到四更短。一次加一可能让数值上升，但随后右移会让规模下降，不应把过程说成每一步都严格减小。

    可用最优剩余步数 f 比较两条路径：偶数有 f(2k)=1+f(k)，大于一的奇数有 f(2k+1)=2+min(f(k),f(k+1))。相邻正整数的最优步数之差至多一，可由这两个式子递归归纳得到。比较奇数两条分支时，先各自完成加减一和随后必需的一次除二，两边都已经花费相同的两步。对 4k+1，减一并除二后的剩余代价是 1+f(k)，加一并除二后是 2+min(f(k),f(k+1))，前者不大于后者；对 4k+3 且 k≥1，对称地选择加一不劣。只有三会直接靠近终点一，需要单独处理。

    解题步骤

    • 先转宽整数，操作次数零。
    • 偶数右移。
    • 奇数为三或低两位零一则减一，其余加一。
    • 每轮计一步，达到一结束。

    十一可走十二、六、三、二、一，共五步；也有另一条同样最优的减一开头路径。

    代码实现

    // 奇数时，若 n == 3 或 n % 4 == 1，选择 n - 1。
class Solution {
    public int integerReplacement(int n) {
        // 先转宽整数，承载最大输入加一的中间值
        long x = n;
        int steps = 0;

        while (x > 1) {
            if ((x & 1) == 0) {
                x >>= 1;
            } else {
                // 低两位决定调整方向，三减一可直接更快到达终点
                if (x == 3 || (x & 3) == 1) {
                    x--;
                } else {
                    x++;
                }
            }

            steps++;
        }

        return steps;
    }
}

    // 奇数时，若 n == 3 或 n % 4 == 1，选择 n - 1。
func integerReplacement(n int) int {
    // 先转宽整数，承载最大输入加一的中间值
    x := int64(n)
    steps := 0

    for x > 1 {
        if x&1 == 0 {
            x >>= 1
        } else {
            // 低两位决定调整方向，三减一可直接更快到达终点
            if x == 3 || x&3 == 1 {
                x--
            } else {
                x++
            }
        }
        steps++
    }

    return steps
}

    复杂度分析

    • 时间复杂度：$O(\log(n+1))$，调整后可以右移，常数次操作使数值规模缩小。
    • 空间复杂度：$O(1)$，当前值与计数。

    关键点总结

    [!green]

    • 贪心选择不必唯一，目标是最少步数而非唯一操作序列。
    • 三的例外由接近终点的两条路径直接比较。

    易错点总结

    [!yellow]

    • 用窄整数承载最大值加一，会回绕成负数。
    • 忽略三的例外，会多走一步。
    • 奇数一律减一，会在十五这样的长连续一位串上失去更短路径。
