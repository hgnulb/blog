    题目描述

    [!blue]
    ✅ 滴滴面试题-合并 k 个排序数组

    给定 N 个有序数组，每个数组的长度为 M，要求将这 N 个有序数组合并成一个有序数组。

    题意分析

    输入是 N 个各自有序的数组，输出是把全部 $NM$ 个元素合并成的一个有序数组。动手前先和面试官确认几点：默认升序、允许重复元素；各数组长度是否一定相同不影响算法，代码按长度可以不同的更通用设定来写；只要求返回完整结果，不要求流式输出。

    最直观的做法是把所有元素拼进一个大数组整体排序，$O(NM \log(NM))$ 时间。能做，但完全没有利用「每个数组本身有序」这个条件，面试中一句带过即可，不要真的写它。

    用上有序条件的关键观察是：合并结果的下一个元素，一定出自各数组「尚未取走的最前面那个元素」——也就是说每一步的候选只有 N 个，答案是这 N 个候选中的最小值。问题于是变成「反复在 N 个动态候选里取最小」，这正是最小堆的标准场景，单次取最小从 $O(N)$ 降到 $O(\log N)$，这就是解法一。

    另一条路线是复用「合并两个有序数组」这个更小的能力，像归并排序的「治」阶段一样分治两两合并，即解法二。两条路线时间复杂度相同，取舍见文末解法对比。

    解法一：最小堆多路归并

    核心思路

    维护一个大小不超过 N 的最小堆，堆中每个节点代表一个数组的「当前最前元素」，记录三元组 （值，所属数组下标，元素下标），按值比较。这样堆顶永远是全部候选中的最小值，也就是合并结果的下一个元素。

    初始把每个非空数组的首元素入堆。之后每一轮弹出堆顶写入结果，再把堆顶所在数组的下一个元素补入堆（若该数组还有剩余）。这个「弹一个、补一个」的节奏保证了一个不变量：每个未取尽的数组在堆中恰好有一个代表，堆的大小始终不超过 N。

    正确性由不变量直接给出：任何还没进入结果的元素，都不小于它所在数组的当前代表，而堆顶是所有代表中的最小值，所以堆顶就是全局剩余元素的最小值，逐个弹出得到的序列必然有序。

    三元组里带上两个下标是为了弹出后能定位「同一数组的下一个元素」，这是多路归并的通用手法，合并 k 个链表时链表节点自带 next，数组版就要自己记下标。

    解题步骤

    • 建堆：遍历 N 个数组，非空的把 (首元素值, 数组下标 i, 元素下标 0) 入堆，同时累加总长度用于预分配结果数组。空数组直接跳过，这一步天然处理了空数组边界。
    • 循环取最小：堆非空时弹出堆顶，把值追加进结果。
    • 补位：设堆顶来自数组 row 的位置 col，若 col + 1 未越界，就把 (arrays[row][col+1], row, col+1) 入堆；越界说明该数组已取尽，堆的规模减一。
    • 结束：堆空时全部元素恰好各进出堆一次，返回结果数组。

    以 arrays = [[1, 4, 7], [2, 5], [3, 6, 8]] 走一遍（堆内只列出值）：

    初始：堆 {1, 2, 3}，结果 []
    弹 1 补 4：堆 {2, 3, 4}，结果 [1]
    弹 2 补 5：堆 {3, 4, 5}，结果 [1, 2]
    弹 3 补 6：堆 {4, 5, 6}，结果 [1, 2, 3]
    弹 4 补 7：堆 {5, 6, 7}，结果 [1, 2, 3, 4]
    弹 5，数组 [2, 5] 已取尽不补：堆 {6, 7}，结果 [1, 2, 3, 4, 5]
    依次弹 6 补 8、弹 7、弹 8，最终结果 [1, 2, 3, 4, 5, 6, 7, 8]。

    代码实现

    class Solution {
    public int[] mergeKArrays(int[][] arrays) {
        // 堆节点为 {值, 所属数组下标, 元素下标}，按值比较
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        int total = 0;

        for (int i = 0; i < arrays.length; i++) {
            total += arrays[i].length;
            if (arrays[i].length > 0) {
                heap.offer(new int[]{arrays[i][0], i, 0});
            }
        }

        int[] result = new int[total];
        int pos = 0;

        while (!heap.isEmpty()) {
            int[] top = heap.poll();
            result[pos++] = top[0];

            int row = top[1];
            int col = top[2] + 1;
            if (col < arrays[row].length) {
                heap.offer(new int[]{arrays[row][col], row, col});
            }
        }

        return result;
    }
}

    type heapItem struct {
    val, row, col int
}

type minHeap []heapItem

func (h minHeap) Len() int           { return len(h) }
func (h minHeap) Less(i, j int) bool { return h[i].val < h[j].val }
func (h minHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

func (h *minHeap) Push(x any) {
    *h = append(*h, x.(heapItem))
}

func (h *minHeap) Pop() any {
    old := *h
    last := old[len(old)-1]
    *h = old[:len(old)-1]
    return last
}

func mergeKArrays(arrays [][]int) []int {
    h := &minHeap{}
    total := 0

    for i, arr := range arrays {
        total += len(arr)
        if len(arr) > 0 {
            heap.Push(h, heapItem{arr[0], i, 0})
        }
    }

    result := make([]int, 0, total)
    for h.Len() > 0 {
        top := heap.Pop(h).(heapItem)
        result = append(result, top.val)

        // 补上同一数组的下一个元素，保证每个数组在堆中恰有一个代表
        if top.col+1 < len(arrays[top.row]) {
            heap.Push(h, heapItem{arrays[top.row][top.col+1], top.row, top.col + 1})
        }
    }

    return result
}

    复杂度分析

    • 时间复杂度：$O(NM \log N)$，其中 N 为数组个数，M 为单个数组的长度。共 $NM$ 个元素，每个元素进出堆各一次，堆大小不超过 N，单次堆操作 $O(\log N)$。
    • 空间复杂度：$O(N)$，不计输出数组，堆中同时最多 N 个节点。

    关键点总结

    • 核心不变量：每个未取尽的数组在堆中恰好有一个代表，弹一个就补一个，堆的大小才能稳定在 $O(N)$。
    • 堆节点必须携带数组下标和元素下标，否则弹出后无法定位下一个待补元素。
    • 建堆时跳过空数组，主循环就完全不用再考虑空数组，边界自然消化。
    • 堆的价值在于把「N 个候选取最小」从 $O(N)$ 降到 $O(\log N)$，这句话就是本解法对暴力排序的全部优势来源。

    解法二：分治两两合并

    核心思路

    换一个视角：合并两个有序数组是我们早就会的 $O(m + n)$ 双指针操作（LeetCode 88），那么合并 N 个数组就可以分治——把 N 个数组从中间分成两半，递归地把每一半各自合并成一个有序数组，再对这两个结果做一次线性归并。这本质上就是归并排序的「治」阶段。

    复杂度的关键在于分层看总量：递归树共 $O(\log N)$ 层，每一层所有归并操作触碰的元素总数都是 $NM$，所以总时间 $O(NM \log N)$，与最小堆持平。

    必须警惕的反面写法是逐个合并：用结果数组依次和第 1、2、…、N 个数组归并。结果数组越滚越长，第 i 次合并的代价是 $O(iM)$，总时间退化为 $O(N^2 M)$。分治的意义就是让每个元素只被归并 $O(\log N)$ 次，而不是 $O(N)$ 次。

    解题步骤

    • 递归函数：divide(arrays, lo, hi) 返回把下标区间 [lo, hi] 内的数组合并后的结果。
    • 递归基：lo == hi 时只剩一个数组，直接返回它。
    • 分：取 mid = (lo + hi) / 2，递归得到左半合并结果和右半合并结果。
    • 治：对两个有序数组做双指针归并——较小者先进结果，一方耗尽后把另一方剩余部分整体追加。
    • 入口：N 为 0 时返回空数组，否则调用 divide(arrays, 0, N - 1)。

    以 arrays = [[1, 5], [2, 6], [3, 7], [4, 8]] 走一遍：

    左半：merge([1, 5], [2, 6]) 得 [1, 2, 5, 6]
    右半：merge([3, 7], [4, 8]) 得 [3, 4, 7, 8]
    顶层：merge([1, 2, 5, 6], [3, 4, 7, 8]) 得 [1, 2, 3, 4, 5, 6, 7, 8]

    两层归并，每层触碰全部 8 个元素，正对应 $O(NM \log N)$ 的分析。

    代码实现

    class Solution {
    public int[] mergeKArrays(int[][] arrays) {
        if (arrays.length == 0) {
            return new int[0];
        }
        return divide(arrays, 0, arrays.length - 1);
    }

    private int[] divide(int[][] arrays, int lo, int hi) {
        if (lo == hi) {
            return arrays[lo];
        }
        int mid = lo + (hi - lo) / 2;
        return mergeTwo(divide(arrays, lo, mid), divide(arrays, mid + 1, hi));
    }

    private int[] mergeTwo(int[] a, int[] b) {
        int[] merged = new int[a.length + b.length];
        int i = 0;
        int j = 0;
        int k = 0;

        while (i < a.length && j < b.length) {
            // 取等时先取 a，保证合并稳定
            merged[k++] = a[i] <= b[j] ? a[i++] : b[j++];
        }
        while (i < a.length) {
            merged[k++] = a[i++];
        }
        while (j < b.length) {
            merged[k++] = b[j++];
        }

        return merged;
    }
}

    func mergeKArrays(arrays [][]int) []int {
    if len(arrays) == 0 {
        return []int{}
    }
    return divide(arrays, 0, len(arrays)-1)
}

func divide(arrays [][]int, lo, hi int) []int {
    if lo == hi {
        return arrays[lo]
    }
    mid := lo + (hi-lo)/2
    return mergeTwo(divide(arrays, lo, mid), divide(arrays, mid+1, hi))
}

func mergeTwo(a, b []int) []int {
    merged := make([]int, 0, len(a)+len(b))
    i, j := 0, 0

    for i < len(a) && j < len(b) {
        // 取等时先取 a，保证合并稳定
        if a[i] <= b[j] {
            merged = append(merged, a[i])
            i++
        } else {
            merged = append(merged, b[j])
            j++
        }
    }
    merged = append(merged, a[i:]...)
    merged = append(merged, b[j:]...)

    return merged
}

    复杂度分析

    • 时间复杂度：$O(NM \log N)$，其中 N 为数组个数，M 为单个数组的长度。递归树共 $O(\log N)$ 层，每层归并的元素总量为 $NM$。
    • 空间复杂度：$O(NM)$，每层归并都会产生与元素总量同级的临时数组，外加 $O(\log N)$ 递归栈。

    关键点总结

    • 分治的复杂度要按层算总量：$\log N$ 层，每层 $O(NM)$，这是面试中最该讲清的一句。
    • 逐个合并是 $O(N^2 M)$ 的退化写法，能主动指出这一点是重要加分项。
    • mergeTwo 用 <= 让相等元素保持原有相对顺序，归并是稳定的。
    • 递归基返回原数组引用即可，不必拷贝，真正的新数组只在归并时产生。

    解法对比

    最小堆：$O(NM \log N)$ 时间、$O(N)$ 额外空间。它是「多路归并」的标准范式：不需要一次性拿到全部数据，天然支持流式输入；只要前 k 小的元素时可以提前停；能原样迁移到合并 k 个升序链表（LeetCode 23）。

    分治两两合并：时间相同，$O(NM)$ 额外空间。优点是不需要手写堆结构、双指针归并访存连续、常数小；缺点是必须拿到全部数据才能开始，且每层归并都有整批临时数组。

    面试建议：主写最小堆，讲清「弹一个补一个」的不变量和 $O(\log N)$ 取最小的来源；随后口述分治作为备选，并主动点出「逐个合并会退化到 $O(N^2 M)$」——这三点合起来基本覆盖了面试官对这道题的全部追问点。

    易错点总结

    • 忘记处理空数组：建堆时对空数组直接取 arrays[i][0] 会越界，必须先判长度再入堆。
    • 弹出后忘记补位：堆里最多只有 N 个元素，不补位会漏掉该数组的剩余元素，结果长度不足。
    • 堆节点只存值不存下标：弹出后无法定位「同一数组的下一个元素」，多路归并无从谈起。
    • 把复杂度答成 $O(NM \log(NM))$：那是暴力整体排序的复杂度，堆解法的对数底数是堆的大小 N，不是元素总数。
    • 分治写成逐个合并：结果数组滚动变长，总时间退化为 $O(N^2 M)$，这是本题最常见的伪最优写法。
    • Go 的 heap.Push / heap.Pop 误用为直接操作切片：必须通过 container/heap 包函数调用才会触发上浮下沉，直接 append 不维护堆序。
