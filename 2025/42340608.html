    题目描述

    [!blue]
    ✅ 小米面试题-最小交换次数（只能交换相邻位置的元素）

    给定一个无序整数数组 nums，你只能交换相邻的元素，求将数组排序成递增顺序所需的最小交换次数。

    题意分析

    面试现场先和面试官对齐约束：只能交换相邻元素。这是本题的题眼——如果允许交换任意两个位置，就是另一道题（答案为 n 减去置换环个数），思路完全不同。另外确认是否有重复元素、数据规模多大：重复元素不影响结论（相等元素无需交换），规模决定 $O(n^2)$ 的暴力能否通过。

    本题的核心结论是：最小相邻交换次数 = 逆序对数。逆序对指满足 i < j 且 nums[i] > nums[j] 的下标对。这个结论要从上下界两个方向论证，面试时说清这两句就足够：

    • 不能更少（下界）：一次相邻交换只改变这两个相邻元素之间的相对顺序，数组中其他任何数对的前后关系都不变，因此每次交换最多让逆序对数减 1。排好序意味着逆序对数降为 0，所以至少需要「初始逆序对数」次交换。
    • 一定够（上界可达）：只要数组还没排好，就必然存在相邻的一对 nums[i] > nums[i + 1]（否则整个数组已单调不减），交换它们恰好让逆序对数减 1。这正是冒泡排序的过程，它用恰好「逆序对数」次交换完成排序。

    下界和上界重合，结论成立。于是问题转化为：高效统计逆序对。双重循环（或直接冒泡计数）是 $O(n^2)$，n 达到 $10^5$ 级别就会超时，需要用归并排序或树状数组优化到 $O(n \log n)$。

    边界：空数组或单元素数组已经有序，答案为 0；逆序对数最多为 $\frac{n(n-1)}{2}$，n 较大时会超出 32 位整数范围，答案要用 64 位整数承接。

    解法一：归并排序统计逆序对

    核心思路

    归并排序按分治把逆序对天然拆成三类：左半区间内部的、右半区间内部的、跨越两半的。前两类由递归解决，跨越两半的在合并阶段统计，三部分相加就是总逆序对数。

    合并阶段的关键观察：此时左右两半各自已有序。当右侧元素 arr[j] 小于左侧当前元素 arr[i] 时，左侧从 i 到 mid 的元素都比 arr[j] 大，且它们的原始下标都在 j 之前，因此一次性贡献 mid - i + 1 个逆序对。正是这个「批量计数」把逐对比较的 $O(n^2)$ 压到了 $O(n \log n)$。

    相等时（arr[i] <= arr[j]）必须先取左侧元素且不计数——相等元素不构成逆序对，无需交换。等号写错方向会把重复元素误算进答案。

    归并会修改数组，为了不破坏调用方的入参，先克隆一份再排；辅助数组 tmp 在最外层分配一次、所有递归层复用，避免每层合并都新建数组。

    解题步骤

    • 入口：数组为空或长度不超过 1 时直接返回 0；否则克隆数组、分配 tmp，进入递归。
    • 递归基：left >= right，单个元素没有逆序对，返回 0。
    • 分：取 mid = left + (right - left) / 2，递归统计左右两半的逆序对并累加。
    • 合：双指针 i、j 分别扫左右两半。arr[i] <= arr[j] 时取左侧；否则取右侧并累加 mid - i + 1。随后把两半剩余元素依次搬入 tmp，最后拷回原区间。
    • 返回：本层计数加上两个子问题的计数。

    以 [3, 1, 2] 走一遍（真实逆序对是 (3,1) 和 (3,2)，共 2 个）：

    递归拆成 [3, 1] 和 [2]。合并 [3] 与 [1] 时，1 < 3，累加 mid - i + 1 = 1，得有序段 [1, 3]，左半内部计 1 个。
    合并 [1, 3] 与 [2]：先取 1（不计数）；接着 2 < 3，累加 mid - i + 1 = 1，得 [1, 2, 3]，跨两半计 1 个。
    总计 $1 + 1 + 0 = 2$，与直接数的结果一致。

    代码实现

    class Solution {
    public long minSwaps(int[] nums) {
        if (nums == null || nums.length <= 1) {
            return 0L;
        }

        int[] arr = nums.clone();
        int[] tmp = new int[arr.length];
        return mergeCount(arr, tmp, 0, arr.length - 1);
    }

    private long mergeCount(int[] arr, int[] tmp, int left, int right) {
        if (left >= right) {
            return 0L;
        }

        int mid = left + (right - left) / 2;
        long count = mergeCount(arr, tmp, left, mid) + mergeCount(arr, tmp, mid + 1, right);

        int i = left, j = mid + 1, k = left;
        while (i <= mid && j <= right) {
            if (arr[i] <= arr[j]) {
                tmp[k++] = arr[i++];
            } else {
                // arr[i..mid] 都大于 arr[j]，一次性贡献 mid - i + 1 个逆序对
                count += mid - i + 1;
                tmp[k++] = arr[j++];
            }
        }
        while (i <= mid) {
            tmp[k++] = arr[i++];
        }
        while (j <= right) {
            tmp[k++] = arr[j++];
        }

        System.arraycopy(tmp, left, arr, left, right - left + 1);
        return count;
    }
}

    func minSwaps(nums []int) int64 {
    if len(nums) <= 1 {
        return 0
    }

    arr := make([]int, len(nums))
    copy(arr, nums)
    tmp := make([]int, len(nums))
    return mergeCount(arr, tmp, 0, len(arr)-1)
}

func mergeCount(arr, tmp []int, left, right int) int64 {
    if left >= right {
        return 0
    }

    mid := left + (right-left)/2
    count := mergeCount(arr, tmp, left, mid) + mergeCount(arr, tmp, mid+1, right)

    i, j, k := left, mid+1, left
    for i <= mid && j <= right {
        if arr[i] <= arr[j] {
            tmp[k] = arr[i]
            i++
        } else {
            // arr[i..mid] 都大于 arr[j]，一次性贡献 mid-i+1 个逆序对
            count += int64(mid - i + 1)
            tmp[k] = arr[j]
            j++
        }
        k++
    }
    for i <= mid {
        tmp[k] = arr[i]
        i++
        k++
    }
    for j <= right {
        tmp[k] = arr[j]
        j++
        k++
    }

    copy(arr[left:right+1], tmp[left:right+1])
    return count
}

    复杂度分析

    • 时间复杂度：$O(n \log n)$，其中 n 表示数组长度。递归共 $O(\log n)$ 层，每层合并的总工作量为 $O(n)$。
    • 空间复杂度：$O(n)$，来自克隆数组与归并辅助数组；递归栈深度为 $O(\log n)$。

    关键点总结

    • 逆序对被分治拆成「左半内部、右半内部、跨两半」三类，合并阶段只负责第三类，这是理解本解法的骨架。
    • 批量计数 mid - i + 1 依赖「左半已有序」这一前提，它是从 $O(n^2)$ 到 $O(n \log n)$ 的关键一步。
    • 相等时先取左侧且不计数，重复元素才不会被误算。
    • 计数器用 64 位整数，逆序对数上限是 $\frac{n(n-1)}{2}$。
    • tmp 在最外层分配一次并复用，比每层递归新建数组更省内存分配开销。

    解法二：树状数组 + 离散化

    核心思路

    换一个视角看逆序对：从左到右扫描数组，对每个元素统计它左边有多少个比它严格大的数，全部累加就是逆序对总数。这需要一个支持「插入一个值、查询不大于某值的个数」的结构，树状数组维护前缀计数正合适，单次操作 $O(\log n)$。

    数组值可能很大或为负，不能直接当树状数组的下标，所以先离散化：排序去重后把每个值映射到 1..m 的排名，只保留大小关系。

    扫描到下标 pos 的值 v 时，树状数组里已插入了 pos 个元素，query(rank(v)) 给出其中不大于 v 的个数，两者相减就是左边严格大于 v 的个数，即以 v 结尾的逆序对数；累加后把 rank(v) 插入树状数组。相等元素被 query 计入「不大于」的部分，天然不会被误算。

    解题步骤

    • 离散化：克隆并排序数组，顺序扫描，首次出现的值依次分配排名 1, 2, 3, …。
    • 建树：按去重后的值域大小 m 建长度为 m + 1 的树状数组，下标从 1 开始。
    • 扫描累加：对每个位置 pos 上的值 v，累加 pos - query(rank(v))，再执行 add(rank(v))。
    • 树状数组操作：add 沿 i += i & -i 向上更新，query 沿 i -= i & -i 向下累加前缀和，i & -i 取出最低位的 1。

    仍以 [3, 1, 2] 走一遍。离散化后排名为 1 → 1、2 → 2、3 → 3。

    pos = 0，值 3：累加 $0 - query(3) = 0$，插入排名 3。
    pos = 1，值 1：累加 $1 - query(1) = 1 - 0 = 1$（左边的 3 比它大），插入排名 1。
    pos = 2，值 2：累加 $2 - query(2) = 2 - 1 = 1$（左边的 3 比它大、1 不算），插入排名 2。
    总计 2，与解法一一致。

    代码实现

    class Solution {
    public long minSwaps(int[] nums) {
        int[] sorted = nums.clone();
        Arrays.sort(sorted);

        // 排序去重后，值 -> 排名（1..m）
        Map<Integer, Integer> rank = new HashMap<>();
        int idx = 1;
        for (int v : sorted) {
            if (!rank.containsKey(v)) {
                rank.put(v, idx++);
            }
        }

        long[] tree = new long[rank.size() + 1];
        long ans = 0L;

        for (int pos = 0; pos < nums.length; pos++) {
            int r = rank.get(nums[pos]);
            // 已插入 pos 个元素，减去不大于当前值的个数，得到左侧严格更大的个数
            ans += pos - query(tree, r);
            add(tree, r);
        }

        return ans;
    }

    private void add(long[] tree, int i) {
        for (; i < tree.length; i += i & -i) {
            tree[i]++;
        }
    }

    private long query(long[] tree, int i) {
        long sum = 0L;
        for (; i > 0; i -= i & -i) {
            sum += tree[i];
        }
        return sum;
    }
}

    func minSwaps(nums []int) int64 {
    sorted := make([]int, len(nums))
    copy(sorted, nums)
    sort.Ints(sorted)

    // 排序去重后，值 -> 排名（1..m）
    rank := make(map[int]int, len(sorted))
    idx := 1
    for _, v := range sorted {
        if _, ok := rank[v]; !ok {
            rank[v] = idx
            idx++
        }
    }

    tree := make([]int64, len(rank)+1)
    add := func(i int) {
        for ; i < len(tree); i += i & -i {
            tree[i]++
        }
    }
    query := func(i int) int64 {
        var s int64
        for ; i > 0; i -= i & -i {
            s += tree[i]
        }
        return s
    }

    var ans int64
    for pos, v := range nums {
        r := rank[v]
        // 已插入 pos 个元素，减去不大于当前值的个数，得到左侧严格更大的个数
        ans += int64(pos) - query(r)
        add(r)
    }

    return ans
}

    复杂度分析

    • 时间复杂度：$O(n \log n)$，其中 n 表示数组长度。排序 $O(n \log n)$，每个元素一次查询一次插入，各 $O(\log n)$。
    • 空间复杂度：$O(n)$，用于离散化映射与树状数组。

    关键点总结

    • 统计口径是「左边严格大于当前值的个数」，用「已插入总数减去不大于的个数」间接求得，等号方向由 query(rank(v)) 天然处理。
    • 离散化只保留大小关系，负数与大值域都不再是问题；排名必须从 1 开始，树状数组下标 0 是非法的。
    • i & -i 取最低位 1 是树状数组的标志性操作，add 向上走、query 向下走。
    • 这个视角与 LeetCode 315「计算右侧小于当前元素的个数」完全同构，掌握一个就通吃一类。

    解法对比

    归并排序：$O(n \log n)$ 时间、$O(n)$ 空间，不需要离散化，代码就是标准归并加一行计数，正确性直接由分治结构保证，是本题的首选写法。

    树状数组 + 离散化：同为 $O(n \log n)$ 时间、$O(n)$ 空间，多了离散化的预处理，但它是在线的——元素逐个到来也能维护计数，且能自然扩展到「每个位置各自的逆序贡献」（如 315 题要求逐位置输出）这类归并不好直接回答的变体。

    面试建议：先讲透「最小相邻交换次数 = 逆序对数」的上下界论证——这一步才是本题的考点核心，然后默认写归并版本；面试官追问「除了归并还有别的办法吗」时给出树状数组思路，并点出离散化的必要性与 315 题的同构关系。

    易错点总结

    • 没有论证就直接写代码：本题考的是「为什么等于逆序对数」，跳过上下界论证等于没答到点上。
    • 混淆两种交换模型：任意交换的最小次数是 n 减去置换环个数，与相邻交换的逆序对模型完全是两道题。
    • 重复元素被计入逆序对：归并中把 arr[i] <= arr[j] 写成 <，或树状数组中用「严格小于」的前缀查询，都会把相等对误算成需要交换。
    • 计数器用 32 位整数：$n = 10^5$ 时逆序对数可达约 $5 \times 10^9$，int 直接溢出。
    • 树状数组下标从 0 开始：i & -i 在 i = 0 时为 0，循环不推进或直接越界，排名必须从 1 起。
    • 归并忘记把 tmp 拷回原数组：两半没有真正变有序，上层合并的批量计数前提被破坏，答案错得很隐蔽。
    • 暴力冒泡计数不问规模：$O(n^2)$ 在 $10^5$ 级别必然超时，报暴力前先和面试官确认数据量。
