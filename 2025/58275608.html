    题目描述

    [!blue]
    ✅ 面试题：最小交换次数（可以交换任意两个位置的元素）

    给定一个无序整数数组 nums，你可以交换数组中任意两个位置的元素，求使数组变为递增序列的最小交换次数。

    题意分析

    先和面试官确认交换规则，这直接决定是哪道题：本题允许交换任意两个位置，答案由置换环决定；如果只能交换相邻元素，答案等于逆序对数，要用归并排序或树状数组统计，是另一道题（见文末相似题目）。

    再确认元素是否互异。本文按面试默认的互不重复推导。若允许重复，相同值可以映射到多个目标位置，「选哪个映射」变成一个会影响答案的匹配问题——例如 [2, 2, 1] 按稳定映射（值相同按原下标排）会算出 2 次，而实际交换一次 (0, 2) 就有序了。代码里比较器带上原下标做次关键字，保证重复元素下映射唯一且结果合法，但那时算出的只是稳定映射下的交换数，不再保证全局最小。

    明确目标后，问题的形式是：给定当前排列和目标排列（排序后的样子），每次交换任意两个元素，最少几次能从前者变到后者。直观贪心是从左到右扫，位置 i 上若不是「排序后应在 i 的元素」，就一次交换把正确元素换过来——每次交换让至少一个位置彻底归位，直觉上不浪费。这个贪心确实最优，但「为什么不可能更少」需要置换环的语言才能说清，这正是本题的考点。

    解法一：置换环分解

    核心思路

    把「每个位置上的元素最终该去哪」抽象成一个置换：对每个位置 i，连一条有向边指向「现在占着 i 的目标元素所在的位置」。由于每个位置的出度和入度都恰好是 1，整张图必然分解成若干互不相交的环——已经归位的元素是长度为 1 的自环，错位的元素在长度 $\geq 2$ 的环里首尾相接地互相占着对方的位置。

    结论是：最小交换次数 = $n - c$，其中 n 是数组长度，c 是环的个数（含自环）。它由上界和下界夹出来。

    上界（$n - c$ 次一定够）：对一个长度为 L 的环，任取环上一个位置，把它该有的元素换过来——这一次交换让一个元素彻底归位，剩下的错位元素仍构成一个长度为 $L - 1$ 的环。归纳下去，$L - 1$ 次交换整个环全部归位。对所有环求和，总次数 $\sum (L_i - 1) = n - c$。这就是前面那个贪心的形式化。

    下界（少于 $n - c$ 次一定不够）：观察一次交换对环结构的影响——交换只涉及两个元素，若它们在同一个环里，环被拆成两个；若在不同环里，两个环合成一个。也就是说一次交换最多让环的个数加 1。终态「完全有序」是 n 个自环，从 c 个环出发，环数至少要增加 $n - c$，所以至少 $n - c$ 次交换。

    上界和下界相等，$n - c$ 就是精确答案。于是算法退化为一件很简单的事：构造置换，数出环的个数。

    解题步骤

    • 构造目标映射：把下标数组 idx = [0, 1, ..., n-1] 按 nums[idx[i]] 升序排序（值相同按下标升序）。排序后 idx[i] 的含义是：最终应放在位置 i 的那个元素，当前在位置 idx[i]，即置换的边 i → idx[i]。
    • 找环：用 visited 数组标记。对每个未访问且 idx[i] != i 的位置 i，沿 j = idx[j] 一路走并标记，直到回到已访问节点，途中经过的节点数就是环长 L。
    • 累加答案：每个环贡献 $L - 1$，累加即得 $n - c$。自环（idx[i] == i）直接跳过，等价于贡献 0。

    以 nums = [4, 3, 2, 1] 走一遍：

    排序后目标是 [1, 2, 3, 4]，它们的原位置依次是 3、2、1、0，所以 idx = [3, 2, 1, 0]。
    从位置 0 出发：0 → 3 → 0，环长 2，贡献 1 次交换（交换位置 0 和 3 的元素）。
    从位置 1 出发：1 → 2 → 1，环长 2，再贡献 1 次。
    答案 $4 - 2 = 2$ 次，对应实际操作：换 (0, 3) 得 [1, 3, 2, 4]，再换 (1, 2) 得 [1, 2, 3, 4]。

    再看 nums = [3, 1, 2]：目标 [1, 2, 3] 的原位置是 1、2、0，idx = [1, 2, 0]，只有一个长度为 3 的环 0 → 1 → 2 → 0，答案 $3 - 1 = 2$ 次，逐位归位可以验证确实要两次。

    代码实现

    class Solution {
    public int minSwaps(int[] nums) {
        int n = nums.length;
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) {
            idx[i] = i;
        }

        // idx[i] = 最终应放在位置 i 的元素当前所在的位置
        Arrays.sort(idx, (a, b) -> nums[a] != nums[b]
                ? Integer.compare(nums[a], nums[b])
                : Integer.compare(a, b));

        boolean[] visited = new boolean[n];
        int swaps = 0;

        for (int i = 0; i < n; i++) {
            if (visited[i] || idx[i] == i) {
                continue;
            }

            int size = 0;
            for (int j = i; !visited[j]; j = idx[j]) {
                visited[j] = true;
                size++;
            }

            swaps += size - 1;
        }

        return swaps;
    }
}

    func minSwaps(nums []int) int {
    n := len(nums)
    idx := make([]int, n)
    for i := range idx {
        idx[i] = i
    }

    // idx[i] = 最终应放在位置 i 的元素当前所在的位置
    sort.Slice(idx, func(a, b int) bool {
        if nums[idx[a]] != nums[idx[b]] {
            return nums[idx[a]] < nums[idx[b]]
        }
        return idx[a] < idx[b]
    })

    visited := make([]bool, n)
    swaps := 0

    for i := 0; i < n; i++ {
        if visited[i] || idx[i] == i {
            continue
        }

        size := 0
        for j := i; !visited[j]; j = idx[j] {
            visited[j] = true
            size++
        }

        swaps += size - 1
    }

    return swaps
}

    复杂度分析

    • 时间复杂度：$O(n \log n)$，其中 n 为数组长度，瓶颈在排序；找环阶段每个位置恰好被访问一次，只需 $O(n)$。
    • 空间复杂度：$O(n)$，下标数组与访问标记各一份。

    关键点总结

    • 答案公式 $n - c$ 必须配上完整论证：环内逐位归位给出上界 $\sum (L_i - 1)$，「一次交换环数至多加 1、终态是 n 个自环」给出下界，两者相等才敢说「最小」。
    • idx 排序后的语义是「目标位置 → 当前位置」的置换，沿 j = idx[j] 走必然回到起点，这是出入度均为 1 的直接推论。
    • 自环零贡献：已归位的元素既不用交换也不影响别的环，代码里用 idx[i] == i 提前跳过。
    • 找环只需要数环长，不需要真的执行交换——面试官若追问「输出具体交换方案」，沿环模拟贪心即可。
    • 比较器带原下标做次关键字，是为了在重复元素下让映射唯一且合法；同时要能说出此时结果未必是全局最小（见题意分析的 [2, 2, 1] 例子）。

    解法对比

    本题任意交换的最优解就是置换环一种，值得对比的是它和几条「近亲」路线的边界。

    置换环（本题）：任意两位置交换，$O(n \log n)$ 时间（若元素是 0..n-1 的排列可省排序，降到 $O(n)$），答案 $n - c$。

    逆序对（相邻交换版）：只能交换相邻元素时，每次交换至多消除一个逆序对，最小次数 = 逆序对数，用归并排序或树状数组 $O(n \log n)$ 统计。两题条件一字之差，模型完全不同，混用是本题最致命的错误。

    暴力 BFS：把数组状态当图节点、一次交换当一条边求最短路，指数级状态数，只能用来对拍验证小规模用例，不可作为解法。

    面试建议：先复述交换规则确认是「任意交换」，然后直接给 $n - c$ 结论并主动讲上下界论证——这道题的区分度几乎全在「为什么不可能更少」这一问上；写码部分反而简单，注意讲清 idx 数组的语义即可。

    易错点总结

    • 和相邻交换版搞混：把本题答成逆序对数，或把相邻交换版答成 $n - c$，是最常见的整题跑偏。
    • 只给贪心不给下界：说「每次归位一个元素所以最优」只论证了上界，没有「环数每次至多加 1」的下界论证，无法回答「为什么不能更少」。
    • 置换方向绕晕：idx[i] 是「应在位置 i 的元素现在在哪」，不是「位置 i 的元素该去哪」；两个方向的环结构相同（互为逆置换），环数一致，但混着用会写出错误的遍历。
    • 忘记跳过自环：不判 idx[i] == i 结果仍正确（环长 1 贡献 0），但白白多一轮循环；判了则顺便让语义更清晰。
    • 重复元素直接套用：不加次关键字排序时映射不唯一，加了次关键字也只是稳定映射下的交换数，不保证全局最小，需要向面试官主动声明假设。
    • Java 用 int[] 存下标再排序：Arrays.sort(int[]) 无法带自定义比较器，要么用 Integer[]，要么把值和下标打包成二维数组排序。
