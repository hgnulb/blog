    题目描述

    ✅ 1298. 你能从盒子里获得的最大糖果数

    题意分析

    拿到盒子和拥有开盒条件是两件事：必须持有盒子，且盒子原本打开或已有钥匙，才能取出其中糖果、钥匙和其他盒子。

    解法：BFS + 状态驱动

    核心思路

    [!blue]
    三种状态分开维护。 hasBox 表示持有盒子，hasKey 表示拿到钥匙，queued 表示已经安排过处理。queued 入队时置真，之后不清除，同时覆盖排队中和已经结算的盒子。

    两类事件共同触发处理。 分别记录持有的盒子与已获得的钥匙。拿到新盒子或新钥匙时，都检查相关盒子是否已具备打开条件，满足才加入待处理队列。

    入队时标记已经安排过，保证一个盒子只结算一次。暂时打不开的盒子仍保留持有状态，之后钥匙到达时还能被唤醒。队列顺序不影响最终可打开集合，收集全部可达糖果即可。

    解题步骤

    1. 标记初始持有的盒子，将其中可打开的去重入队。
    2. 取出一个盒子并累加糖果。
    3. 登记新钥匙；对应盒子已持有且尚未安排时入队。
    4. 登记内含盒子；它已解锁且尚未安排时入队。
    5. 处理到没有新的可开盒子为止。

    示例：先打开盒子 0，取得锁着的盒子 1 和可开的盒子 2；打开 2 后取得钥匙 1，才能再打开 1。必须在获得钥匙时重新检查已有锁盒，不能只在第一次拿到盒子时判断。 三只可开盒子的糖果依次为 7、4、5，共 16；盒子 1 内另有锁盒 3，但没有钥匙，不能取走其中的糖。

    代码实现

    class Solution {
    public int maxCandies(
            int[] status, int[] candies, int[][] keys, int[][] containedBoxes, int[] initialBoxes) {
        int n = status.length;
        boolean[] hasBox = new boolean[n];
        boolean[] hasKey = new boolean[n];
        boolean[] queued = new boolean[n];

        ArrayDeque<Integer> queue = new ArrayDeque<>();

        for (int b : initialBoxes) {
            hasBox[b] = true;
        }

        for (int b : initialBoxes) {
            if (status[b] == 1 && !queued[b]) {
                queued[b] = true;
                queue.offer(b);
            }
        }

        int total = 0;

        while (!queue.isEmpty()) {
            // 队列只包含持有、可打开且首次安排的盒子。
            int box = queue.poll();

            total += candies[box];

            for (int k : keys[box]) {
                // 先记录钥匙，再尝试唤醒已经持有的对应锁盒。
                hasKey[k] = true;

                if (hasBox[k] && !queued[k]) {
                    // 入队时就标记安排过，避免重复结算。
                    queued[k] = true;
                    queue.offer(k);
                }
            }

            // 新盒子也可能早已有钥匙，另一种到达顺序同样要检查。
            for (int b : containedBoxes[box]) {
                hasBox[b] = true;

                if (!queued[b] && (status[b] == 1 || hasKey[b])) {
                    queued[b] = true;
                    queue.offer(b);
                }
            }
        }

        return total;
    }
}

    func maxCandies(status []int, candies []int, keys [][]int, containedBoxes [][]int, initialBoxes []int) int {
    n := len(status)
    hasBox := make([]bool, n)
    hasKey := make([]bool, n)
    queued := make([]bool, n)

    queue := make([]int, 0)
    for _, b := range initialBoxes {
        hasBox[b] = true
    }
    for _, b := range initialBoxes {
        if status[b] == 1 && !queued[b] {
            queued[b] = true
            queue = append(queue, b)
        }
    }

    total := 0
    for head := 0; head < len(queue); head++ {
        // 队列只包含持有、可打开且首次安排的盒子。
        box := queue[head]
        total += candies[box]

        for _, k := range keys[box] {
            // 先记录钥匙，再尝试唤醒已经持有的对应锁盒。
            hasKey[k] = true
            if hasBox[k] && !queued[k] {
                // 入队时就标记安排过，避免重复结算。
                queued[k] = true
                queue = append(queue, k)
            }
        }

        // 新盒子也可能早已有钥匙，另一种到达顺序同样要检查。
        for _, b := range containedBoxes[box] {
            hasBox[b] = true
            if !queued[b] && (status[b] == 1 || hasKey[b]) {
                queued[b] = true
                queue = append(queue, b)
            }
        }
    }

    return total
}

    复杂度分析

    • 时间复杂度：$O(n+K+B)$，K、B 分别为钥匙列表和内含盒子列表的总长度，每个已打开盒子的列表只处理一次。
    • 空间复杂度：$O(n)$，保存状态数组和待处理队列。

    关键点总结

    [!green]

    • 持有与解锁缺一不可。
    • 两个条件可能按任意顺序到达，两类事件都要尝试安排。
    • 一旦入队就标记，避免多条线索重复结算同一个盒子。

    易错点总结

    [!yellow]

    • 只有钥匙就立即结算：可能尚未拿到对应盒子。
    • 锁盒第一次打不开就丢弃：后来拿到钥匙时无法再找到它。
    • 仅在一种事件发生时检查：会漏掉另一种先后顺序。
    • 不区分发现与首次安排：同一盒子可能被重复加入并计糖。
