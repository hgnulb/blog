    题目描述

    ✅ 153. 寻找旋转排序数组中的最小值

    题意分析

    在元素互不相同的旋转升序数组中找出最小值，返回数值而不是下标。数组也可能未发生有效旋转，不能依赖一定存在一个下降位置。

    解法：二分定位旋转断点

    核心思路

    [!blue]

    比较中点和右端点。若 nums[mid] > nums[right]，最小值严格位于中点右侧，可以令 left = mid + 1；否则最小值可能就是中点，也可能在左侧，只能令 right = mid。

    最小值始终保留在闭区间内，直到两端相遇。[3, 1, 2] 的中点正好是最小值 1，写成 right = mid - 1 会直接丢失答案。未旋转数组使用同样的比较也会逐步收缩到首元素。

    解题步骤

    1. 初始化闭区间 [left, right] = [0, n-1]，答案一定在其中。
    2. 当 left < right 时取中点 mid。
    3. 若 nums[mid] > nums[right]，最小值只可能在 [mid+1, right]，更新 left = mid + 1。
    4. 否则最小值位于 [left, mid]，更新 right = mid，注意保留 mid。
    5. left == right 时返回 nums[left]。以 [4,5,6,7,0,1,2] 为例，区间依次收缩为 [4,6]、[4,5]、[4,4]。

    代码实现

    class Solution {
    public int findMin(int[] nums) {
        int left = 0;
        int right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            // 中点在较高段时，最小值必在它右侧。
            if (nums[mid] > nums[right]) {
                left = mid + 1;
            } else {
                // 中点自身仍可能最小，必须保留。
                right = mid;
            }
        }

        return nums[left];
    }
}

    func findMin(nums []int) int {
    left := 0
    right := len(nums) - 1

    for left < right {
        mid := left + (right-left)/2
        // 中点在较高段时，最小值必在它右侧。
        if nums[mid] > nums[right] {
            left = mid + 1
        } else {
            // 中点自身仍可能最小，必须保留。
            right = mid
        }
    }

    return nums[left]
}

    复杂度分析

    • 时间复杂度：$O(\log n)$，每轮都将候选区间缩小约一半。
    • 空间复杂度：$O(1)$，只使用常数个下标变量。

    关键点总结

    [!green]

    • 二分搜索的不一定是目标值，也可以是两种性质的分界点。
    • 只有能证明 mid 不可能是答案时才能写 mid + 1；否则必须保留 mid。
    • while (left < right)、下取整中点和 right = mid 是配套模板，不会产生空区间或死循环。
    • 若元素可重复，nums[mid] == nums[right] 时只能 right--，最坏会退化为 $O(n)$，这就是 154 题的区别。

    易错点总结

    [!yellow]

    • 与左端点比较后直接排除一半：未旋转的 [1,2,3] 很容易被误判，右端点才是这套判断的稳定参照。
    • nums[mid] < nums[right] 时写 right = mid - 1：在 [3,1,2] 中会丢掉答案 nums[mid] = 1。
    • 循环使用 left <= right，同时仍写 right = mid：当区间只剩一个元素时无法收缩，会死循环。
    • 把条件写成 >= 并照搬到含重复元素的题：相等时无法判断最小值在哪边，不能直接舍弃一半。
    • 中点写成 (left + right) / 2 有整数溢出风险，应写 left + (right-left)/2。
